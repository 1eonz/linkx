
## 六、后续代码文件格式与要求汇总

> 本章是"当前需求后续代码"的**格式基准与验收要求**：新增端、新增用例、改 Skill 均按本章执行。

### 6.1 dev-bridge 文件格式与要求

| 文件 | 格式要求 |
|------|---------|
| `<端>/provider.js` | 薄配置：`import.meta.env.DEV` 包裹 + URL 判 `bridge !== 'stub'` → `createProvider({...})`；全局型 SDK 用默认 `getSDK`，**模块单例型必须覆写 `getSDK`**（见 5.2.1） |
| `<端>/stub.js` | 薄配置：DEV + `bridge === 'stub'` → `createSdkStub({...})`；全局型用默认 `installStub`（defineProperty 锁定），**模块单例型覆写 `installStub` 挂全局占位**（见 5.2.2） |
| `<端>/stub-config.js` | `EVENT_REGISTER_METHODS`（Set 白名单）+ `envSpoofs`（按端启用的伪造钩子数组） |
| `<端>/bridge-events.js` | `[{ method, handlerField }]`，与 stub-config 白名单保持一致（provider 侧拦截 ↔ stub 侧存 cb） |
| `page-scripts/*`、`proxy-server/server.js` | 协议主干，**各端不复制、不修改**，经 vite alias `@dev-bridge` 引用 |

**全局变量约定**（调试入口与占位桩，命名固定不可改）：

| 变量 | 含义 |
|------|------|
| `window.__bridgeStub` / `__bridgeProvider` | 桩/Provider 调试入口（`status()`） |
| `window.__bridgeReady` | 桩已连上代理（e2e `waitForBridgeReady` 依据） |
| `window.__WE_SPACE_SDK_STUB__` | BSPC 桩占位（post.js initSDK 钩子采用） |
| `window.__WE_SPACE_SDK_INSTANCE__` | BSPC 模块单例暴露（provider 的 getSDK 源 / e2e 调用入口） |

**硬性要求**：
- 所有桥代码副作用必须包裹 `if (import.meta.env && import.meta.env.DEV)`，生产 build 自动剔除
- 新端桥端口按 `8x87/8x88` 规律错开，支持 `BRIDGE_WS_PORT`/`BRIDGE_HTTP_PORT` 覆盖
- 禁止在适配层写协议逻辑（转发/重连/超时均属协议主干）

### 6.2 e2e 用例文件格式与要求（spec.js 骨架模板）

```javascript
/**
 * <功能域>用例集 —— 同名 <功能域>.spec.md 为用例事实来源，
 * js 中每个 test() 必须能在 md 步骤表找到对应行（Skill 校验项）。
 */
import { expect, hasProvider, test } from '../fixtures/host-page.js';

test.describe('<分组：SDK 调用类（依赖宿主在线）>', () => {
  test('<子用例名，与 md 步骤表行一致>', async ({ hostPage }) => {
    // 1. 宿主离线降级（依赖宿主的用例必须，防误报）
    test.skip(!(await hasProvider(hostPage)), '宿主未连接代理，跳过 SDK 调用测试');
    // 2. 前置就位（单例占位 / 路由 / 等待选择器）
    await hostPage.waitForFunction(() => !!window.__WE_SPACE_SDK_INSTANCE__, {
      timeout: 20000,
    });
    // 3. 操作 + 断言（预期结果以 md 为准，禁止为通过率改断言）
    const result = await hostPage.evaluate(async () => {
      try {
        return {
          ok: true,
          data: await window.__WE_SPACE_SDK_INSTANCE__.<method>(),
        };
      } catch (e) {
        return { ok: false, error: String((e && e.message) || e) };
      }
    });
    expect(result).toHaveProperty('ok');
  });
});

test.describe('<分组：页面结构类（不依赖宿主）>', () => {
  test('<子用例名>', async ({ hostPage }) => {
    await expect(hostPage.locator('<选择器>')).toBeVisible();
  });
});
```

### 6.3 e2e 用例 md 文件格式与要求（spec.md 模板）

```markdown
# <端>-<功能域>用例集

- 用例编号：<端大写>-<功能域大写>-<三位序号>（如 BSPC-LOGIN-001）
- 所属端：<端>（e2e/<端>/tests/<功能域>.spec.js）
- 优先级：P0 / P1 / P2
- 执行方式：auto / manual / partial（部分自动化）

## 前置条件

1. <环境 / 服务 / 宿主要求，逐条列出>

## 用例步骤

| # | 子用例 | 步骤 | 预期结果 | 依赖宿主 | 自动化状态 |
|---|--------|------|---------|----------|-----------|
| 1 | <与 js test() 同名> | <操作步骤> | <可验证的预期> | 是/否 | auto/manual |

## 自动化说明

- <降级策略 / partial 时必须注明未自动化的步骤及原因>

## 手动验证记录

| 验证人 | 日期 | 结论 | 证据（截图/录屏链接） |
|--------|------|------|----------------------|
```

**双文件硬性要求**（承接 3.7）：

1. 先写/改 md，后写/改 js；md 是用例事实来源，断言与 md 冲突时以 md 为准
2. js 每个 `test()` 标题必须与 md 步骤表"子用例"列一致（Skill 写/跑两侧均校验）
3. 无法自动化的用例**只建 md 不建 js**，"自动化状态"标 `manual`，并在"手动验证记录"登记
4. 文件按功能域组织（`login.spec.*` / `collaboration.spec.*` …），禁止一个大文件塞所有用例
5. 依赖宿主的用例必须 `test.skip(!hasProvider(...))` 降级；`workers: 1` 串行执行
6. spec.md 不进 Playwright 执行（`testDir` 只匹配 `*.spec.js`），仅作为文档与 Skill 事实源

### 6.4 业务仓库接入点格式与要求

| 接入点 | H5Portal 型（window 全局 SDK） | BSPC 型（模块单例 SDK） |
|--------|------------------------------|-------------------------|
| vite 配置 | `resolve.alias` + `@dev-bridge`；`server.fs.allow` 放行仓库根 | 同左（web 在自身 `vite.config.mts` 包装，不改共享包） |
| TS 声明 | —（JS 项目） | `types/dev-bridge.d.ts` 环境模块声明（vue-tsc 构建需要） |
| 入口接入 | main.js **顶部静态 import stub**（SDK 模块顶层副作用）；**底部 DEV 分支动态 import provider** | main.ts 顶部静态 import stub；**bootstrap 内桩短路宿主桥** + DEV 预热 `initSDK()` + 动态 import provider |
| SDK 桩点 | 无需改业务代码（stub-core 锁定 `window[sdkName]`） | **post.js `initSDK` DEV 钩子**采用 `__WE_SPACE_SDK_STUB__`；成功后挂 `__WE_SPACE_SDK_INSTANCE__` |
| 生产验证 | `pnpm build` 后产物 grep `__bridge` 为空 | 同左（另 grep `__WE_SPACE_SDK_` 为空） |

### 6.5 Skill 文件格式与要求

- 路径固定：`.trae/skills/frontend-unit-test-writer/SKILL.md`、`.trae/skills/frontend-unit-test-runner/SKILL.md`（单文件，无其他依赖）
- 结构：frontmatter（name/description）→ 触发条件 → 核心工作流 → 命令模板 → 输出格式 → 约束（全文见第四章）
- E2E 章节为**追加性质**：保留 Vitest 基线全文，E2E 扩展追加在对应章节尾部，触发条件含"e2e 目录 / Playwright / spec.md"关键词
- writer 与 runner 的 spec.md 规则必须一致（双文件约定、manual 处理、md 为事实来源）

### 6.6 全局验收要求（Checklist）

| # | 要求 | 验证方式 |
|---|------|---------|
| 1 | 生产零残留：产物中无 `__bridge` / `__WE_SPACE_SDK_` | build 后 grep 产物 |
| 2 | 桥端口不冲突：多端并行 `8x87/8x88` 错开 | 5.5 端口速查表 |
| 3 | 用例双文件齐全且对应 | Skill 校验 + code review |
| 4 | 宿主离线不误报 | 断开宿主跑 e2e，SDK 类用例全部 skip |
| 5 | 串行执行 | config `workers: 1, fullyParallel: false` |
| 6 | 协议主干零改动 | 各端只新增 `<端>/` 适配层 |
| 7 | md 为事实来源 | 断言与 md 冲突时改 js 不改 md（除非需求变更先改 md） |

### 7.2 验证清单（重建完成的判定标准）

- [ ] `curl http://localhost:8798` → `{"providerConnected":false,...}`
- [ ] 宿主加载 dev 页面后 `providerConnected:true`，宿主 console 有 `[bridge provider] connected`
- [ ] 本地浏览器打开 stub 入口：console `[bridge stub] connected`；`window.__bridgeStub.status()` 可读；页面以宿主数据渲染
- [ ] `pnpm test:bspc` 全绿（或宿主离线时 SDK 类 skip，skip 原因在报告中注明）

### 7.3 常见问题速查

| 现象 | 原因 | 处置 |
|------|------|------|
| Playwright 报 port already used | 终端带 `CI=1` 使 `reuseExistingServer` 失效 | PowerShell 先 `$env:CI=''` 再跑 |
| webServer https 就绪探测失败 | basicSsl 自签证书被探测请求拒绝 | 先手动 `cd web && pnpm dev`，再跑测试（reuseExistingServer 复用已有服务） |
| 宿主 WebView2 打不开 dev 页面 | 自签 https 被宿主证书校验拦截 | dev 阶段临时关闭 vite `https`（`server.https`）改用 http，或宿主侧（仅开发环境）忽略证书错误 |
| stub 页面白屏/挂起 | bootstrap 桩短路未生效（检查 main.ts 静态 import 位于顶部、`__WE_SPACE_SDK_STUB__` 已挂），或宿主推送类状态在短路后缺失 | 核对 5.3-①；缺失状态的默认初始化纳入短路分支 |
| `providerConnected` 一直 false | 宿主未加载 dev 页面 / 不在同一网段 / 代理端口不符 | 宿主访问 `https://<本机IP>:3100/`；确认 `proxy:bspc`（8797/8798）已启动；检查防火墙 |
| SDK 调用 30s 超时 | 宿主在 invokeRetry 窗口（60s）内未上线，或方法名宿主不支持 | 先开宿主再触发调用；确认方法名；健康检查确认在线 |
| vue-tsc 报 Cannot find module '@dev-bridge' | 缺环境模块声明 | 补 `web/types/dev-bridge.d.ts`（5.3-④） |
| H5Portal 与 BSPC 同时跑互相干扰 | 两端共用同一代理端口 | 各端独立代理实例（proxy:h5portal 8787/8788，proxy:bspc 8797/8798） |
| 产物中残留 `__bridge` | DEV 包裹遗漏 | 按第六章 6.1/6.4 检查所有桥代码副作用 |

### 7.4 后续新端接入速查（一句话流程）

> 适配层四件套（全局型用默认 `installStub`/`getSDK`，模块单例型按 BSPC 覆写）→ 业务仓库接入（vite alias + 入口 import + TS 声明 + SDK 桩点钩子）→ `e2e/<端>/` 四件套（fixture / config / 首批 spec 双文件）→ 端口按 `8x87/8x88` 错开 → 按 5.6 验证 → 用两个 Skill 维护用例与报告。
