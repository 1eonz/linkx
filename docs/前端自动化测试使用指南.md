# Linkx 前端自动化测试使用指南

本文对应仓库根目录的 `e2e` 和 `dev-bridge`。测试目标分为：

| 目标 | 页面/宿主 | SDK 通信 |
| --- | --- | --- |
| `h5portal` | H5Portal + H5 APP | `flutterNativeBridge` |
| `web-bspc` | web 浏览器 + BSPC 宿主 | `SETUP_CHANNEL` + `MessagePort` |
| `web-cspc` | web + PC APP WebView2 | `chrome.webview`，模拟时必须 `PIM_GetPlatform() === 'win'` |

每个目标有两种模式：`offline` 使用真实前端、原始 SDK、业务请求 mock 和宿主传输模拟；`live` 使用本地页面 Stub、内网宿主 Provider 和真实业务后端。原生 APP 弹窗、宿主导航和真实选人界面不能由浏览器 Playwright 直接替代，须在 live 或人工验收中记录。

## 一、新电脑准备

在仓库根目录打开 PowerShell，使用与各项目锁文件匹配的 Node/pnpm 版本。

```powershell
pnpm --dir e2e install --frozen-lockfile
pnpm --dir dev-bridge install
pnpm --dir H5Portal install --frozen-lockfile
pnpm --dir web install --frozen-lockfile
pnpm --dir e2e exec playwright install chromium
```

如果项目使用的 pnpm 版本启用了构建脚本审批，首次安装 H5/web 依赖后按终端提示批准项目已有的 `esbuild`、`@parcel/watcher`、`core-js`（web 还可能包含 `vue-demi`）构建脚本，然后重新执行安装。不要把审批提示中的占位字符串写入 `pnpm-workspace.yaml`；审批配置应使用当前项目 pnpm 版本支持的布尔值格式。

如果 Chromium 下载源不可用，可使用本机安装的 Chrome 或 Edge：

```powershell
cd e2e
$env:E2E_BROWSER_CHANNEL = 'chrome' # 或 msedge
pnpm run test:contracts
```

不要提交 `node_modules`、`e2e/reports`、测试 token 或内网账号。

## 二、离线契约验证

契约 harness 直接读取三份原始 SDK 文件，不修改 SDK 文件，也不需要 H5/web dev server。

```powershell
cd e2e
pnpm run typecheck
$env:E2E_BROWSER_CHANNEL = 'chrome' # 机器有 Playwright Chromium 时可删除
pnpm run test:contracts
```

契约用例验证用户信息、并发请求 ID、错误、事件和 ACK、storage 编码及 popup 注入。BSPC 没有 storage API，因此该能力会有一个明确跳过项；这不是失败。

## 三、离线真实页面

先启动页面，或令 Playwright 自动启动：

```powershell
# 终端 1，可选：手动启动
pnpm --dir H5Portal dev
pnpm --dir web dev

# 终端 2
cd e2e
$env:E2E_BROWSER_CHANNEL = 'chrome'
$env:E2E_START_SERVERS = '0' # 手动启动时使用；自动启动改为 1
pnpm run test:offline
```

单目标运行：

```powershell
$env:E2E_TARGET = 'h5portal'
pnpm run test:offline
$env:E2E_TARGET = 'web-bspc'
pnpm run test:offline
$env:E2E_TARGET = 'web-cspc'
pnpm run test:offline
```

offline 用例会严格拦截未配置的 XHR/fetch/业务 WebSocket。出现 `Unconfigured API` 时，应根据真实源码接口补充 Scenario，而不是放宽拦截。报告在 `e2e/reports/offline/html`，失败用例还会附宿主调用和业务请求 JSON。

如果页面启动前出现 `ERR_PNPM_IGNORED_BUILDS`、`esbuild` 缺失或 husky `.git can't be found`，先完成前面的依赖脚本审批并重新安装；不要把页面未启动误判为业务用例通过。

当前代表性流程：

- H5 `/pages/createGroup`：标签选择、创建接口、错误/取消/授权过滤、错误 groupId 事件、匹配 `onCooperationGroupCreate` 后 `sms`、`switchTab`、`close`。
- BSPC/CSPC `/statics`：自定义建群的选人差异、创建接口、SDK 后续聊天动作及取消/错误分支。

完整范围见 `e2e/coverage-matrix.md`。

## 四、本地桥接联调

普通浏览器 Stub 只在开发环境且 URL 明确带 `bridge=stub` 时启用。宿主页面使用 `bridge=provider`，不带参数不会自动连接桥。

### H5

```powershell
cd dev-bridge
pnpm run proxy:h5portal # WS 8787，健康检查 8788

# 另一个终端
pnpm --dir H5Portal dev
```

让 H5 APP 通过内网可访问的本机 IP 打开 `http://<本机IP>:8001/linkx/h5portal/`，宿主页面使用 `?bridge=provider`。浏览器联调打开 `http://localhost:8001/linkx/h5portal/?bridge=stub`。

### BSPC/CSPC

分别启动：

```powershell
pnpm --dir dev-bridge proxy:web-bspc # 8887/8888
pnpm --dir dev-bridge proxy:web-cspc  # 8987/8988
pnpm --dir web dev                   # 默认 https://localhost:3100
```

web Vite 已配置同源 `/__dev_bridge/<target>/socket` 和 `/health` 代理。HTTPS 页面必须使用 WSS 或同源代理，不要在浏览器中直接混用 `ws://`。BSPC Provider 依赖宿主发送 `SETUP_CHANNEL` 并完成 `READY`；CSPC Stub 在 SDK 加载前提供 WebView2 API 和 `PIM_GetPlatform='win'`。

检查 Provider：

```powershell
curl http://127.0.0.1:8888/health?session=local
curl http://127.0.0.1:8988/health?session=local
```

返回 `providerConnected: true` 后，才运行 live。多窗口或多台测试机必须使用不同 `E2E_BRIDGE_SESSION`，Provider 和 Stub 会按目标及会话隔离。

## 五、内网 live 测试

live 不会把宿主未连接转成绿色跳过。先确认：

1. 测试机能访问内网宿主和业务 API。
2. H5 APP、BSPC 或 CSPC 已加载本地 dev 页面并以 Provider 角色连接正确端口。
3. 测试电脑浏览器能访问本机 IP 页面；不要把 `localhost` 写入远程模拟器地址。
4. 证书、Windows 防火墙、Vite host 和 WebSocket/WSS 端口已放行。

```powershell
cd e2e
$env:E2E_MODE = 'live'
$env:E2E_TARGET = 'web-cspc'
$env:E2E_WEB_URL = 'https://<测试机IP>:3100/'
$env:E2E_BRIDGE_SESSION = 'cspc-machine-a'
$env:E2E_BRIDGE_HEALTH_URL = 'https://<测试机IP>:3100/__dev_bridge/web-cspc/health'
$env:E2E_BROWSER_CHANNEL = 'chrome'
pnpm run test:live
```

H5 使用 `E2E_H5_URL`，BSPC/CSPC 使用 `E2E_WEB_URL`。如果健康检查失败，先修复 Provider、目标、会话或端口；不要加 `test.skip`。

## 六、证据和人工验收

Playwright 结果只证明页面 DOM、业务网络、SDK 调用/事件和桥接协议。以下项目必须在内网宿主手工确认并附截图或录屏：

- 原生选人弹窗确实打开、选中结果返回且关闭行为正确。
- `openUrl`、`openPage`、`openChatUI`、`sms` 等宿主导航/弹窗显示正确。
- H5 APP 和 PC APP 的真实登录、权限、版本和业务数据。
- Provider 重连、宿主重载、多个 Stub 会话的隔离。

记录目标、宿主版本、SDK 版本、前端 commit、后端地址、测试数据 ID、时间和报告路径。

## 七、增加新用例

1. 在源码确认路由、接口、SDK 参数和事件名称。
2. 在对应目标目录新增 `tests/<case>.offline.spec.ts` 或 `.live.spec.ts`。
3. 离线 API/WS 只在该用例的 Scenario 中配置；宿主方法用 `host.on`，异步通知用 `host.emit`。
4. 同目录新增 `<case>.spec.md`，写前置数据、业务步骤、断言和人工步骤。
5. 更新 `e2e/coverage-matrix.md`。
6. 运行 typecheck、contracts、目标 offline；内网可用时再运行 live。

## 八、故障排查

| 现象 | 处理 |
| --- | --- |
| `Live environment unavailable` | 检查目标端口、session、Provider 健康检查和前端地址 |
| H5 页面 SDK 调用无响应 | 确认 Stub/Provider 角色、H5 URL 参数和 8787/8788；H5 不应伪造 CSPC 的 PIM 平台 |
| BSPC `READY timed out` | 确认宿主处理 `SETUP_CHANNEL`、MessagePort 未被其他脚本消费 |
| CSPC SDK 走移动端逻辑 | Stub 必须在 SDK 动态导入前设置 `PIM_GetPlatform() === 'win'` |
| `Unconfigured API` | 读取前端实际请求和响应契约，补充 Scenario，不要放宽 strict mock |
| `provider replaced` | 同一 target/session 只运行一个 Provider，或为不同宿主使用不同 session |
| 业务页面白屏 | 先用真实前端 dev server 直接打开页面，再检查 bridge URL、Vite alias 和浏览器控制台 |

## 九、迁移旧工程

`linkx-e2e` 是早期试验目录，不再作为三目标 canonical runner。新用例统一放入 `e2e`；保留旧目录用于对照和迁移，迁移前必须重新检查目标 SDK、事件编码和真实页面，不要直接复制其 placeholder transport 或 skip 逻辑。
