# 错误码体系规范

> 参考: 阿里巴巴 Java 开发手册（错误码章节）、HTTP Status Codes

## 一、错误码设计原则

- 错误码全局唯一，跨服务不冲突
- 错误码可读性强，能快速定位问题
- 错误码分段管理，按服务/模块划分
- 错误码与 HTTP 状态码配合使用，不替代

## 二、错误码格式

### 2.1 格式定义

```
{服务编码(2位)}{模块编码(2位)}{错误类型(2位)}{序号(2位)}
```

总长度: 8 位数字

### 2.2 服务编码

> 服务编码段分配表见 `.trae/rules/backend.md` §5（项目特有资源分配）。预留 91-99，新增服务编码由架构组分配。

### 2.3 模块编码

| 编码 | 模块 | 说明 |
|------|------|------|
| 00 | 通用 | 不属于特定模块 |
| 01 | 认证 | 登录/Token/权限 |
| 02 | 用户 | 用户管理 |
| 03 | 角色 | 角色管理 |
| 04 | 菜单 | 菜单/权限 |
| 05 | 配置 | 系统配置 |
| 06 | 文件 | 文件上传/下载 |
| 07 | 日志 | 操作日志 |
| 08 | 代码生成 | 代码生成器 |

> 模块编码由各服务内部定义

### 2.4 错误类型编码

| 编码 | 类型 | 说明 |
|------|------|------|
| 00 | 成功 | 请求成功 |
| 01 | 系统错误 | 服务端内部错误 |
| 02 | 参数错误 | 请求参数校验失败 |
| 03 | 认证错误 | 未登录/Token 无效 |
| 04 | 权限错误 | 无访问权限 |
| 05 | 业务错误 | 业务规则校验失败 |
| 06 | 数据错误 | 数据不存在/已存在/冲突 |
| 07 | 外部错误 | 第三方服务调用失败 |
| 08 | 限流错误 | 请求被限流 |
| 09 | 降级错误 | 服务降级 |

## 三、错误码定义

### 3.1 全局通用错误码 (900000-909999)

| 错误码 | HTTP 状态码 | 描述 |
|--------|-------------|------|
| 900000 | 200 | 成功 |
| 900100 | 500 | 系统内部错误 |
| 900101 | 500 | 数据库操作失败 |
| 900102 | 500 | 缓存操作失败 |
| 900103 | 500 | 消息队列操作失败 |
| 900200 | 400 | 参数校验失败 |
| 900201 | 400 | 缺少必填参数 |
| 900202 | 400 | 参数格式错误 |
| 900203 | 400 | 参数超出范围 |
| 900300 | 401 | 未认证 |
| 900301 | 401 | Token 无效 |
| 900302 | 401 | Token 已过期 |
| 900303 | 401 | 认证方式不支持 |
| 900400 | 403 | 无权限 |
| 900401 | 403 | 角色无权限 |
| 900402 | 403 | 资源无权限 |
| 900500 | 200 | 业务处理失败（通用） |
| 900600 | 404 | 数据不存在 |
| 900601 | 409 | 数据已存在 |
| 900602 | 409 | 数据冲突 |
| 900700 | 502 | 第三方服务调用失败 |
| 900701 | 504 | 第三方服务超时 |
| 900800 | 429 | 请求限流 |
| 900900 | 503 | 服务降级 |

### 3.2 系统服务错误码 (100000-109999)

| 错误码 | 描述 |
|--------|------|
| 100101 | 用户名或密码错误 |
| 100102 | 账号已禁用 |
| 100103 | 账号已锁定 |
| 100104 | 验证码错误 |
| 100201 | 用户已存在 |
| 100202 | 用户不存在 |
| 100203 | 旧密码不正确 |
| 100301 | 角色已存在 |
| 100302 | 角色不存在 |
| 100303 | 角色下存在用户，无法删除 |

### 3.3 各服务自定义

各服务在自身编码段内定义业务错误码，遵循统一格式。

## 四、ErrorCode 枚举定义

```java
@Getter
@AllArgsConstructor
public enum ErrorCode {

    // 全局通用
    SUCCESS(900000, "操作成功"),
    SYSTEM_ERROR(900100, "系统内部错误"),
    DB_ERROR(900101, "数据库操作失败"),
    PARAM_INVALID(900200, "参数校验失败"),
    PARAM_MISSING(900201, "缺少必填参数"),
    UNAUTHORIZED(900300, "未认证"),
    TOKEN_INVALID(900301, "Token无效"),
    TOKEN_EXPIRED(900302, "Token已过期"),
    FORBIDDEN(900400, "无权限"),
    DATA_NOT_FOUND(900600, "数据不存在"),
    DATA_EXISTS(900601, "数据已存在"),
    EXTERNAL_ERROR(900700, "第三方服务调用失败"),
    EXTERNAL_TIMEOUT(900701, "第三方服务超时"),
    RATE_LIMITED(900800, "请求限流"),
    SERVICE_DEGRADED(900900, "服务降级"),

    // 系统服务
    LOGIN_FAILED(100101, "用户名或密码错误"),
    ACCOUNT_DISABLED(100102, "账号已禁用"),
    ACCOUNT_LOCKED(100103, "账号已锁定"),
    CAPTCHA_ERROR(100104, "验证码错误"),
    USER_EXISTS(100201, "用户已存在"),
    USER_NOT_FOUND(100202, "用户不存在"),
    OLD_PASSWORD_ERROR(100203, "旧密码不正确");

    private final int code;
    private final String message;
}
```

## 五、错误响应格式

### 5.1 内部接口

```json
{
  "code": 1,
  "message": "用户名或密码错误",
  "data": null
}
```

### 5.2 开放接口

```json
{
  "code": 1,
  "message": "用户名或密码错误",
  "data": null
}
```

> 开放接口额外提供 `solution` 字段，指导开发者解决问题

## 六、错误码管理

- 错误码集中定义在 `ErrorCode` 枚举中，禁止硬编码数字
- 新增错误码必须同步更新文档
- 错误码一旦发布不可修改含义，只能废弃新增
- 废弃的错误码标记 `@Deprecated`，至少保留 6 个月
